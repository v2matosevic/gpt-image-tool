# gpt-image-tool 0.7.0: Studio

Give your coding agent a workspace for image work, not just a button that makes
one picture.

## What Studio is, and who it is for

Studio is for people who have an agent make more than one or two images: a set
of variations, a look to settle before a page is built, a draft to take to a
finished asset. Instead of a pile of separate calls, the agent builds the work
as a graph. Prompts, lists and references feed generators. Unchanged images are
reused, not made again. Every image records what made it. An approved image
becomes a build package for a coding agent, and a screenshot of the result comes
back onto the graph to compare.

Studio also keeps the agent honest about what it looked at. Every image is
measured against its prompt (colour, light, composition, focus, black bars),
and an agent has to record a look before it can approve an image. For a person,
`gpt-image studio page` writes a plain side-by-side page of the results, and
`gpt-image studio view` shows the graph in a local, read-only browser page.

Studio organises and measures. It has no taste of its own and does not make an
image better by itself.

Agents use nine new MCP tools (`studio_guide` first); people and programs use
`gpt-image studio ...` on the command line. The full guide is
[STUDIO.md](https://github.com/v2matosevic/gpt-image-tool/blob/v0.7.0/docs/STUDIO.md).

## Subscription first; the paid API only when chosen

Everyday images stay on your ChatGPT subscription, the default for every tool
and every Studio node. The paid OpenAI API is used only where you ask for it:
`backend: "apikey"` on a call, `renderer: "api"` on a Studio node, or a Studio
`finish` node, which re-renders an approved draft from its pixels at up to 4K.
No profile or environment setting can move a node to the API, and nothing falls
back from one to the other.

Use the API when someone will look at the image at full size, print it, ship it
as a hero or brand asset, or when it needs a size or precision the subscription
cannot give. A cheap draft first, then a finish of the chosen one, is the
pattern: on November 28 a 2.6 low 1024 px draft cost 2.5 cents and a Sunburst
high 2048 px finish 11.6 cents.

Every paid request, from Studio or any direct tool call, is checked against
spend limits before it is sent:

| Limit | Default | Raised by |
| --- | --- | --- |
| Per Studio run, or per direct tool call | $2 | a grant, or `studio.limits.run` in the project's `.gptimage.json` |
| Per project per day | $10 | a grant, or `studio.limits.day` |
| Project ceiling | $50 | only `studio.limits.ceiling`; no grant lifts it |
| All projects per day | $25 | a grant (up to the user ceiling), or `~/.gptimage/config.json` |
| User ceiling | $100 | only `~/.gptimage/config.json` |

A request past a limit is refused before anything is sent, with the fix. When
you approve more in chat, the agent records your words as a grant with
`studio_budget`; a grant ends with the day. This is a guard against runaway
mistakes by a cooperating agent, not a security boundary.

## Also in this release

- GPT-Image-2.6 on the paid API: `flare` (fast) and `sunburst` (precise, the
  API default), `complexity`, custom sizes up to 3840 px on an edge, and each
  result's cost from the usage the API reported. The key can come from
  `OPENAI_API_KEY`, the project's git-ignored `.secrets` or
  `~/.gptimage/secrets`; results name where it came from, never the key.
- The subscription's image-cap error states when the cap resets, and a stopped
  Studio run records that time.
- The MCP server is bundled into one file, so cold starts on a busy disk no
  longer time out.
- The reasoning block is no longer sent with subscription image requests.
- An optional perception pack adds similarity to an anchor image and a
  foreground mask from small local models. It is not installed by default.

## Upgrade notes

**Paid API users:** `flare` and `sunburst` now mean GPT-Image-2.6, and the API
default is `gpt-image-2.6-sunburst`. In v0.6.0 they meant 2.5. To stay on 2.5,
write `flare-2.5` / `sunburst-2.5` or the full ID in calls, profiles and
`GPT_IMAGE_API_MODEL`. Images replayed from a sidecar keep the model they were
made with. On 2.6, low and medium quality use more output tokens, so they cost
more than on 2.5; high costs the same. Spend limits now apply to every paid
request; raise them in your own files if your use needs more.

Subscription users: nothing changes in how images are made or billed. Studio
needs no setup; graphs are stored under `.gptimage/studio/` in each project.

Use Node.js 22.18 or newer:

```sh
git clone --branch v0.7.0 https://github.com/v2matosevic/gpt-image-tool.git
cd gpt-image-tool
npm ci
npm run build
npm run smoke:mcp
```

Existing installations: follow the
[upgrade instructions](https://github.com/v2matosevic/gpt-image-tool/blob/v0.7.0/docs/SETUP.md#upgrade-an-existing-installation),
then reconnect MCP. The server reports `0.7.0` and exposes 22 tools.

## What is verified, and what is not

Verified live, on one Windows machine and one account, November 27 and 28:

- Studio graphs built, run, reviewed and approved by agents on the
  subscription (a product set, sweeps from an anchor image, canon entries and
  lessons), including a fresh agent working from the guide alone, and the
  read-only viewer.
- The paid API through Studio and through a direct MCP call under the limits:
  2.6 Flare and Sunburst drafts, Sunburst finishes at 2048 px and 3840 x 2160,
  and reported costs matching OpenAI's calculator (824 output tokens against 823
  for a low 1024 px image). A six-prompt comparison on both renderers with two 4K
  finishes cost $0.48 in all.
- The perception pack installed and run on real images on that machine.
- On the subscription, the quality value sent is not validated: `high`, `max`
  and a nonsense value all returned images reported as quality `low`. Studio
  therefore does not claim `high` improves a subscription image.

Verified offline only (tests with fakes and mocked HTTP, on Windows locally and
on Windows, macOS and Linux in CI): spend-limit refusals at each level, grants,
the user-level limit, ledgers that fail closed, the clock rules, resume chains,
the stop at the subscription image cap, a run outliving the MCP server that
started it, and the handoff and implementation nodes.

Not verified:

- Grants against the real API. No grant was recorded live.
- GPT-Image-2.5 (`flare-2.5`, `sunburst-2.5`) live in this release; only 2.6 was
  run against the API.
- The perception pack's download size (about 518 MB, the figure the install
  command shows first) on a clean machine, and the pack on macOS or Linux. It
  stays opt-in.
- The depth-of-field measure ("soft share") is calibrated on twelve images: two
  shallow-focus portraits read 0.49 and 0.51, ten other images 0.01 to 0.31.
  The letterbox check flagged one image in 294 local images, the one that had
  bars. Treat both as measurements to confirm by looking.
- Anything on macOS or Linux beyond CI's offline tests and MCP smoke check.
- Image quality. These checks show that the tool works as described, not that
  either renderer is better.

## Known issue

`npm audit` reports one high-severity advisory: `zod` 3, which this tool uses to
validate tool inputs, can exhaust memory when validating oversized input
([GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)). The
fix is zod 4, a breaking upgrade that changes validation messages and the MCP
tool schemas, so it is left for a later release rather than rushed into this one.
The server reads input only from the local agent that started it over stdio, so
exposure is limited to that agent. Every other reported advisory is fixed:
`@modelcontextprotocol/sdk` 1.32.2, `sharp` 0.35.5 and compatible transitive
updates.
